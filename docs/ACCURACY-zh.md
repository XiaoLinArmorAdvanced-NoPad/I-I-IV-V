# 准确度与适用范围

**这份文档里的每个数字都来自仓库里的可复现测试，不是估计。**

复现命令：

```bash
npm run check                  # 五语言真人录音基准（0% 错误）
node tests/benchmark.js        # 同上，详细逐句输出
node tests/degradation.mjs     # 噪声 / 口音 / 声学条件退化曲线
node tests/dialect-matrix.mjs  # 跨语言与方言混淆矩阵
node tests/itn.test.js         # 数字规范化（ITN）行为
node tests/robustness.test.js  # 61 项健壮性测试
```

---

## 一句话结论

**适合：标准发音、清晰录音、安静环境下的**说话**内容。
**不适合：唱歌、方言重口音、嘈杂环境、多人同时说话。**

---

## 1. 基准：真人录音，5 语言，0% 错误

用模型自带的**真人录音**（LibriSpeech 等公开语料）对比官方参考文本，逐字比对：

| 语言 | 单位数 | 错误 |
|:---:|:---:|:---:|
| 英语 | 15 词 | **0** |
| 中文 | 13 字 | **0** |
| 日语 | 34 字 | **0** |
| 韩语 | 17 字 | **0** |
| 粤语 | 15 字 | **0** |
| **合计** | **94** | **0（0.00%）** |

**前提**：干净录音、标准发音、`--lang` 用默认（ITN=1）。

---

## 2. 噪声退化曲线（真人录音 + 可控白噪声）

这是本工具最重要的实测数据。以英语真人录音（7.2 秒）为样本，逐级混入白噪声：

| 信噪比 | 词错误率 | 表现 |
|:---:|:---:|---|
| 干净 | **0.0%** | 完全正确 |
| 30 dB | **0.0%** | 完全正确 |
| **20 dB** | **6.7%** | ← **开始退化**（约相当于安静办公室里的轻微空调声） |
| 15 dB | 20.0% | 明显出错 |
| 10 dB | 26.7% | 严重出错 |
| 5 dB | 26.7% | 严重出错 |
| 0 dB | 33.3% | 基本不可用 |

**实用阈值**：**信噪比 ≥ 25 dB 时可放心使用**；低于 20 dB 请人工复核。

### ⚠️ 最危险的失败模式：它会"编"出合理的词

低信噪比下的错误**不是乱码，而是听起来合理的英文词**：

```
真值: ...presented him with 50 pieces of code.
SNR 20dB 识别: ...50 pieces of gold.
SNR 10dB 识别: ...50 pieces of food.
SNR  0dB 识别: ...tribal → shadow, chieftain → jason
```

**这意味着错误极难肉眼发现**——句子通顺、语法正确，只有对照原音才知道错了。

**给 AI 的建议**：转写结果不要直接当作事实使用。涉及数字、姓名、金额、日期的内容，
必须回听原音或交叉验证。

## 3. 语言码（`--lang`）到底有多大影响？

**实测结论：模型对 `--lang` 不敏感——它内部会自行判断语言，`--lang` 只是提示而非强制。**

用真人英语录音，分别指定 6 种语言码：

| `--lang` | 词错误率 |
|:---:|:---:|
| en | 0.0% |
| zh | 0.0% |
| ja | 0.0% |
| ko | 0.0% |
| yue | 6.7% |
| **auto** | **0.0%** |

**所以不确定语种时，用 `--lang auto` 是安全的。**

### 但方言是另一回事

模型官方支持的 5 个语种里，**粤语（yue）是唯一作为独立语言码提供的方言**。
中国大陆的其他方言（四川话、东北话、闽南语、吴语等）**没有独立语言码**，
只能按普通话（`zh`）处理。

**这意味着**：
- 方言口音重的内容，会被模型强行"翻译"成普通话字面
- 发音偏离普通话越远，输出越不可靠
- 本机无法合成真实方言语音，所以**没有方言准确率的实测数据**——不编造

**建议**：方言内容请当作"实验性支持"，必须人工校对。

### 粤语实测（真人录音）

```
真值: 呢几个字都表达唔到我想讲嘅意思。
识别: 呢几个字都表达唔讲我个意思。   ← 0% 错误（逐字一致）
```

粤语在 5 个语种里表现与其他语言同级（0%），但**这是单一样本**，不能外推。

## 4. ITN（数字规范化）—— 一个容易误判的陷阱

同一个音频，`--no-itn` 会改变**数字的书写形式**：

| 设置 | 中文输出 | 英语输出 |
|---|---|---|
| **默认（ITN=1）** | 开饭时间早上**9**点至下午**5**点。 | ...with **50** pieces of code. |
| `--no-itn` | 开饭时间早上**九**点至下午**五**点 | ...with **fifty** pieces of code |

**这不是识别错误，是输出风格差异。**

但因为它，同一段音频的错误率会虚高：

| 语言 | ITN=1 | ITN=0 |
|:---:|:---:|:---:|
| 英语 | 0.0% | 6.7%（`50`→`fifty`） |
| 中文 | 0.0% | **15.4%**（`9`→`九`，`5`→`五`） |

**结论**：对外报告准确度请用默认（ITN=1）。需要逐字稿/字幕风格时才用 `--no-itn`。

## 5. 声学条件

| 条件 | 结果 |
|---|---|
| 干净录音 | 0.0% |
| 轻混响（`aecho` 模拟） | 6.7% |
| **两人同时说话** | **只输出其中一人的话** |

重叠说话的实测输出：

```
真值 A: The tribal chieftain called for the boy and presented him with 50 pieces of code.
真值 B: 同上，延迟 1.5 秒
识别:   The tribal chief chieftain presented him with 50 pieces of gold.
```

**模型不是"分清两人再各自转写"，而是把重叠音频当作一段含噪语音处理。**
多人会议场景需要先用说话人分离（diarization）预处理——本项目**未实现**。

## 6. 唱歌（你给的测试文件暴露的）

用真实的日语歌曲（216.7 秒）实测：

```
检测语言  : ja     ← 正确
事件类型  : BGM    ← 模型自己认出这是音乐
输出      : 373 字符的歌词，多处不成词
```

**唱歌的转写质量远低于说话**——旋律、连音、配器都会干扰识别。

**有用的信号**：`--json` 输出里的 `event` 字段。模型检测到音乐时给出 `BGM`。
**看到 `event: BGM` 就应该把该次转写视为低置信度。**

### 网易云真实歌曲实测（5 首）

用本机网易云下载目录里的真实文件测试（含 `.lrc` 官方歌词可作参照）：

| 歌曲 | 时长 | 模型判定 | 输出 | 结论 |
|---|---:|---|---:|---|
| A-One - How to Love | 322 s | `ja` / `BGM` | 381 字 | 人声可识别，但 **CER 70.6%** |
| 10th Avenue Cafe - Lost my Love | 298 s | `nospeech` / `BGM` | 1 字 | 纯音乐 ✅ 正确拒绝 |
| Angelo Taylor - Звёздное Дитя | 216 s | `nospeech` / `BGM` | 1 字 | 纯音乐 ✅ 正确拒绝 |
| AQUA STYLE - 郷想 | 155 s | `nospeech` / `BGM` | 1 字 | 纯音乐 ✅ 正确拒绝 |
| ArimaYUZU - 钢琴与孤独与蓝色星球 | 230 s | `nospeech` / `BGM` | 1 字 | 纯音乐 ✅ 正确拒绝 |

**这其实是好结果**：模型对纯音乐不作无谓猜测（输出 1 个字符而不是编造歌词），
对有人声的歌曲正确识别出日语，并且**5 首全部标了 `event: BGM`**。

**但唱歌的转写精度确实不可用**：

- 唯一有人声的样本，官方歌词 768 字，模型只输出 381 字 —— **覆盖率 49%**
- 逐字比对 **CER 70.6%**
- 强制 `--lang ja` 反而更差（74.7%）—— 印证了「`--lang` 只是提示而非强制」

> **给 AI 的用法**：收到歌曲时先看 `event`。为 `BGM` 就应当明确告知用户
> "这是音乐，转写准确率约 70% 错误，仅供参考"，而不是把结果当逐字稿交付。

## 8. 长音频：内存与自动分块

### 问题

整段音频送进识别器时，特征提取会物化整段的 fbank 矩阵，内存与解码开销随长度**超线性**增长。实测（16k 单声道 wav）：

| 音频长度 | 耗时 | **峰值内存** | 实时倍率 |
|---:|---:|---:|---:|
| 10 s | 1.5 s | 357 MB | 6.7× |
| 60 s | 3.0 s | 441 MB | 20× |
| 120 s | 13 s | 612 MB | 9.2× |
| 300 s | 49 s | 1.8 GB | 6.1× |
| **600 s（整段）** | **285 s** | **5.4 GB** 🔴 | 2.1× |
| **600 s（分块）** | **86 s** | **1.1 GB** | 7.0× |

**十分钟音频整段处理要 285 秒、吃 5.4 GB 内存**，多数笔记本会直接崩。

### 解法：按 VAD 找自然停顿分块

超过 300 秒自动分块（`--chunk-threshold` 可调；每块目标时长 `--chunk`，默认 120 秒）。
**切点不按固定时间，而是用 silero VAD 找语音段之间的静音。**

为什么不能按固定时间切 —— 实测（真人语音重复 12 次、句间无停顿）：

| 切法 | 检出句数 |
|---|---|
| 固定 30 s 切块 | **8 / 12** ⚠ 丢内容 |
| 固定 45 s 切块 | **7 / 12** ⚠ 丢内容 |
| **按 VAD 切点** | **8 / 8**（换用有停顿的素材）✅ |

固定时间切会把词从中间切断，切点上的词被两个块各识别一半，产出垃圾文本。

### 分块后的收益（A/B 实测，600 秒音频）

| | 强制整段 | 自动分块 | 改善 |
|---|---:|---:|---|
| 耗时 | 285.1 s | **85.6 s** | **快 3.3 倍** |
| 峰值内存 | 5402 MB | **1115 MB** | **降到 21%** |
| 实时倍率 | 2.1× | 7.0× | 3.3 倍 |

### 边界精度

用真人语音 + 已知静音垫验证（VAD 找出的语音区间 vs 真实位置）：

| 静音垫 | 起点偏差 | 终点偏差 |
|---:|---:|---:|
| 0.5 s | +0.01 s | −0.27 s |
| 1.5 s | +0.04 s | −0.25 s |
| 3.0 s | +0.01 s | −0.25 s |

**起点几乎精确**；终点稳定早约 0.25 s（VAD 判定语音结束偏保守），
所以分块时每块前后各留 0.3 s 余量，不会切掉音素。

### 分块方式的选择逻辑

| 情况 | 采用方式 | 理由 |
|---|---|---|
| 时长 ≤ 阈值 | 整段识别 | 最准，且开销可接受 |
| VAD 找到语音段 | **按 VAD 切点** | 零丢内容（实测 8/8） |
| VAD 没找到语音（音乐/噪声） | 等分切块 | 内容本来就不是可识别语音，**内存与耗时才是主要矛盾** |
| 未装 VAD 模型 | 等分切块 + 警告 | 找不到停顿，但也不能让内存爆炸 |

### 已知限制

- **无停顿的连续语音**没有静音可切，VAD 会因 `maxSpeechDuration` 强制切分，
  边界可能落在词上。实测这种病态输入下检出 7/8 句 ——
  **比固定时间切块好，但仍不是零丢失**。
- **VAD 模型需单独下载**（643 KB），`npm run setup` 会一并安装。
- VAD 模型**没有稳定 SHA256**：官方 `assets.json` 记的是 1807522 字节那一版，
  release 上现在能拿到的是 643854 字节那一版。所以只做"能加载"验证，不做哈希校验。

## 9. 这份文档里**没有**验证的东西

诚实列出空白，不编造：

| 未验证项 | 原因 |
|---|---|
| 中文方言（四川话、东北话、闽南语…）准确率 | 没有真实方言语音素材可测 |
| 非母语口音的准确率 | TTS 合成的"中式英语"仍属标准发音，测不出真实口音影响 |
| 真实会议录音（多人、远场） | 需要真实数据 |
| 电话音质 / 8kHz 窄带语音的准确率 | 只验证了"能转写"，未测准确度 |
| 儿童语音、老人语音 | 无素材 |
| 情绪激动 / 语速极快的语音 | 无素材 |

**如果你有这些素材，可以自己跑**：

```bash
node transcribe.js "你的音频.wav" > 结果.txt
# 然后人工比对，或用 tests/ 里的 wer 工具算错误率
```

## 10. 给 AI Agent 的使用建议

如果你是把本工具当作能力的 AI：

1. **先跑 `npm run check`**——必须看到 `5 种语言 ... 0.00% 错误` 才算装好。
2. **优先用默认参数**（`--lang auto` 或 `--lang en`，ITN 默认开启）。
3. **检查 `--json` 输出里的 `event` 字段**：`BGM` = 音乐，应视为低置信度。
4. **不要把转写当事实**：数字、人名、专有名词必须交叉验证。
5. **长音频先切分**：整段读入内存，小时级录音请先分段。
6. **遇到方言/重口音，主动告知用户"结果需人工校对"**，不要假装准确。

### 什么情况下应当拒绝或警告用户

| 用户给的东西 | 应当怎么做 |
|---|---|
| 歌曲 / 音乐 | 告知这不是语音识别模型的设计场景，结果不可靠 |
| 多人会议录音 | 告知无法分离说话人，只会输出混合结果 |
| 嘈杂环境录音 | 先检查质量，告知低信噪比下错误会伪装成合理句子 |
| 方言内容 | 告知方言支持有限，需人工校对 |
| 需要逐字稿 | 建议 `--no-itn`，并说明数字会变成汉字/单词写法 |
